Küsi oma andmebaasilt häälega

Üks HTML-fail Spring Booti sisse: räägid eesti keeles, Chrome muudab kõne tekstiks ja saadab selle sinu POST /api/ask endpointile. Java-koodi ei muuda.

  • 🎤 Räägid
  • →
  • Chrome: kõne → tekst
  • →
  • POST /api/ask
  • →
  • Gemini → SQL
  • →
  • Vastus ekraanil

Mida on vaja

Töötav workshop-rakendusnl-to-sql-chat jookseb ja /api/ask vastab Swaggeris
Google Chromekõnetuvastus (Web Speech API) töötab eesti keelega ainult Chrome'is, Safari ei sobi
Mikrofon + internetChrome saadab heli Google'i kõneserverisse, offline ei tööta

Kolm sammu

  1. Loo fail src/main/resources/static/index.html

    Kausta static projektis veel pole, loo see. Kleebi faili allolev kood täpselt sellisena. Spring Boot serveerib kõik static kaustas oleva automaatselt aadressilt /.

  2. Taaskäivita rakendus

    Peata jooksev bootRun (Ctrl+C) ja käivita uuesti: ./gradlew bootRun. Staatilised failid loetakse ainult käivitusel, ilma taaskäivituseta näed 404-i.

  3. Ava Chrome'is http://localhost:8080/

    Vajuta 🎤 Räägi, luba mikrofon, küsi näiteks „Mitu klienti meil on?". Kui lause lõpeb, saadetakse küsimus ise ära ja vastus ilmub alla. Enne 4. sammu on vastus SQL-lause, pärast seda lause loomulikus keeles.

<div class="row">
  <input id="q" placeholder="Küsimus, nt: Mitu klienti meil on?">

<div id="status"></div>

<script>
const $ = id => document.getElementById(id);
const SR = window.SpeechRecognition || window.webkitSpeechRecognition;

async function ask() {
  const question = $('q').value.trim();
  if (!question) return;
  $('status').textContent = 'Küsin…';
  $('ask').disabled = true;
  try {
    const r = await fetch('/api/ask', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ question })
    });
    const data = await r.json();
    $('out').textContent = data.answer ?? JSON.stringify(data, null, 2);
    $('status').textContent = r.ok ? '' : 'Viga ' + r.status;
  } catch (e) {
    $('status').textContent = 'Viga: ' + e.message;
  } finally {
    $('ask').disabled = false;
  }
}

$('ask').onclick = ask;
$('q').addEventListener('keydown', e => { if (e.key === 'Enter') ask(); });

if (!SR) {
  $('mic').disabled = true;
  $('status').textContent = 'Kõnetuvastus vajab Chrome\'i.';
} else {
  const rec = new SR();
  rec.lang = 'et-EE';
  rec.interimResults = true;
  rec.maxAlternatives = 1;
  let listening = false;

  rec.onstart = () => { listening = true; $('mic').classList.add('rec'); $('mic').textContent = '⏹ Lõpeta'; $('status').textContent = 'Kuulan…'; };
  rec.onresult = e => {
    let text = '';
    for (const res of e.results) text += res[0].transcript;
    $('q').value = text;
    if (e.results[e.results.length - 1].isFinal) { $('status').textContent = ''; ask(); }
  };
  rec.onerror = e => { $('status').textContent = 'Kõnetuvastuse viga: ' + e.error; };
  rec.onend = () => { listening = false; $('mic').classList.remove('rec'); $('mic').textContent = '🎤 Räägi'; };

  $('mic').onclick = () => { listening ? rec.stop() : rec.start(); };
}
</script>
</body>
</html>
Oluline rida on rec.lang = 'et-EE'. Ilma selleta tuvastab Chrome inglise keelt ja „mitu klienti" muutub millekski muuks.

Kui ei tööta

Nupp „Räägi" on hall ja kiri „Kõnetuvastus vajab Chrome'i"
Oled Safaris või Firefoxis. Ava sama aadress Chrome'is.
Mikrofoni luba ei küsitud või andsid „Keela"
Aadressiribal klõpsa lukuikooni → Mikrofon → Luba, siis värskenda lehte.
Viga network
Google'i kõneserver pole kättesaadav (VPN, tulemüür, võrk maas). Kirjuta küsimus kasti käsitsi ja vajuta Küsi.
Viga not-allowed
macOS-is: Süsteemiseaded → Privaatsus ja turvalisus → Mikrofon → luba Chrome.
Leht annab 404
Fail on vales kaustas või rakendust ei taaskäivitatud. Tee peab olema täpselt src/main/resources/static/index.html.
Vastus on Viga 500
Probleem on Java pooles, mitte lehes. Vaata sama küsimust Swaggeris ja rakenduse logi.

Kui tahad ka häälvastust

Macil ja Chrome'is eesti keele sünteeshäält sisseehitatuna ei ole, brauseri speechSynthesis loeb eesti teksti inglise aktsendiga. Korralik eesti hääl tuleb eraldi teenusest (nt Jutusta.ee, ElevenLabs-ühilduv API): üks lisaendpoint Javas, mis võtab vastuse teksti ja tagastab WAV-i, ning leht mängib selle ette. Võti jääb serverisse.
